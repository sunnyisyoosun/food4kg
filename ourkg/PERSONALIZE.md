# 개별 추천 — KNHANES × ourkg 설계 계획

> **아직 하나도 측정하지 않았다.** 이 문서는 **계획**이다. 수치가 나오면
> `RESULTS.md` 에 절을 열고, 결론만 이쪽으로 당겨 온다. 계획과 결과를 같은
> 문서에 섞으면 "하려던 것" 과 "된 것" 이 구별되지 않는다.

작성 2026-11-27. 과제 요구는 "KNHANES 로 **개별** 추천" 이고, 우리가 이미 가진
KG 와 **합쳐서** 하려는 것이다.

---

## 0. 이것은 세 번째 트랙이다

| 트랙 | 하는 일 | 위치 |
|---|---|---|
| 역설계 + 부분 재현 | 논문 입력을 되짚어 수치를 맞춘다 | `analyse/` · `REPRODUCTION.md` |
| 재구축 + 확장 | 현재 공개 데이터로 다시 만든다 (**집단** 추천) | `ourkg/` |
| **개별 추천** | 개인 데이터로 사람마다 다른 답을 낸다 | **이 문서** |

앞 두 트랙과 **섞지 않는다.** 특히 평가 기준이 다르다 — 앞 트랙은 "논문 Top30
과 겹치는가" 로 재는데, 개별 추천은 **사람마다 답이 달라야 성공**이므로 그 자를
쓸 수 없다. 자를 따로 정한다 (§6).

그리고 이 트랙의 가치 기준도 논문 답 재현율이 아니다 — `METHODS.md` §0 과 같다.
"개별성이 실제로 나오는가 · 영양학적으로 틀리지 않는가 · 근거를 추적할 수
있는가" 로 고른다.

## 1. 설계 한 줄

> **개인 데이터는 compound 공간에서만 쓰고, 음식 추천은 우리 `F` 가 한다.**

KNHANES 식품코드와 FDC 음식을 1:1 로 잇는 일(수천 건 수작업)을 피하는 유일한
길이다. KNHANES 가 주는 **개인별 영양소 섭취 총량**을 `NUT2KEGG`
(`nhanes.py`) 와 같은 방식으로 KEGG 축에 올리면, 개인과 우리 KG 가 **compound
라는 공통 축**에서 만난다.

```
KNHANES 개인 영양소 총량 ──NUT2KEGG──> 개인 compound 벡터
                                            │
우리 KG: E (극성) · F (음식×compound) · S ──┴──> 개인별 음식 순위
```

예외는 방법 D(협업필터) 뿐이다. 거기만 음식 축 매핑이 필요하고, 그래서 뒤로
미룬다 (§4-D).

## 2. 데이터 받기

### 확인된 것

- **승인 절차는 없다.** 과거의 이메일 로그인 → 이용계획서 → 요청승인 절차를
  질병관리본부가 폐지했다. 홈페이지에서 조사연도 → 이용지침서 → 데이터파일
  순으로 **즉시** 받는다. 형식은 **SAS 또는 SPSS 중 선택**.
  (학회 공지 2건, §9 출처)
- **PHQ-9 은 2년 주기**로 들어간다. **2014 · 2016 · 2018 · 2020 · 2022** 가
  확인된다. 판정은 `PHQ-9 >= 10` 이 관행이고 `nhanes.py` 와 같은 기준이다.
- 받는 곳: https://knhanes.kdca.go.kr/knhanes/rawDataDwnld/rawDataDwnld.do
  (자바스크립트로만 렌더링된다 — `curl`·fetch 로는 API 에러 JSON 만 온다.
  브라우저로 들어가야 한다.)

### 아직 확인 안 된 것

- 회원가입이 필요한지. (2012~2014 년 학회 안내에는 "회원가입 후" 라고 적혀
  있으나 현재 화면을 확인하지 못했다.)
- 메뉴에 `원시자료` 와 별도로 **`학술연구자료신청(절차/신청안내)`** 이 있다.
  후자는 연계DB·제한자료용으로 보이고 일반 원시자료는 아닐 것으로 **추정**한다.
  확인 필요.
- 현재 제공 파일이 `sas7bdat` 인지, 주기별로 어떤 단위로 쪼개지는지.

### 받을 것

| | 무엇 | 왜 |
|---|---|---|
| 1 | 2014 · 2016 · 2018 · 2020 (가능하면 2022) SAS 파일 | PHQ-9 수록 주기 |
| 2 | **각 연도 이용지침서(변수 코드북)** | 변수명이 주기마다 바뀐다. 이것 없이는 못 쓴다 |
| 3 | 식품섭취조사 중 **개인별 영양소 총량** 쪽 | §1 설계가 쓰는 것. 식품단위 상세(`NUTR`)가 아니다 |
| 4 | 건강설문(우울 PHQ-9) · 검진(혈압·혈당·지질·eGFR·BMI) | E 추정과 §4-C 제약 |

### 읽을 때의 함정

- `pd.read_sas(path, format='sas7bdat', encoding='cp949')` — **인코딩이
  함정**이다. 기본값으로 읽으면 한글 레이블이 깨진다.
- `.sav` 를 고르면 `pyreadstat` 의존성이 는다. README 설치 목록을 안 늘리려고
  SAS 쪽을 쓴다 (`nhanes.py` 가 `statsmodels` 를 피한 것과 같은 이유).
- **복합표본설계다.** 가중치(`wt_itvex` 등)·층·집락을 안 쓰면 추정이 편향된다.
  `nhanes.py` 는 가중치를 쓰지 않으니, 여기서 보정하면 그 자체가 개선 항목이다.
- 주기를 합칠 때 가중치를 **주기 수로 나눠야** 한다. 그냥 쌓으면 표본이
  과대평가된다.

## 3. 그대로 붙이면 깨지는 세 곳

이미 레포에 기록된 실패라 미리 못 박는다. **이 셋을 안 막으면 전에 기각된 것과
똑같은 결과가 나온다.**

### (1) 음식 축이 다르다
KNHANES 는 국가표준식품성분표 식품코드, 우리 `F` 는 FDC 음식.
→ **막는 법:** §1 의 compound 공간 설계. 방법 D 만 예외.

### (2) `F` 의 100 g 기준 — 가장 위험하다
`E_MODE=nhanes` 도 (`RESULTS` §15d), `all+auto` 도 (§12) **같은 이유로
기각**됐다. 말린 향신료·영양 강화 분말이 상위를 먹는다. g/100 g 기준에서
미량영양소 농도가 극단적으로 높기 때문이다.

개인화하면 미량영양소 가중이 **더 커지므로 이 문제가 악화된다.**
→ **막는 법:** 개인 추천에는 **1회 섭취량(FNDDS portion) 기준 `F`** 를 쓴다.
§15e 에서 서빙 기준 `F` 를 기각했지만 그건 **논문 재현 지표**로 잰 것이고,
개별 추천에서는 판단이 달라진다. 다시 켠다.
→ **게이트:** Top-10 에 향신료·강화분말·시럽통조림이 들어오면 **그 설정은
버린다** (§6 마지막 줄).

### (3) `E` 는 집단 평균이라 개인화가 아니다
`D = E × Fᵀ` 는 모든 사람에게 같은 값이다. `E` 나 `D` 중 하나를 사람에 따라
바꾸지 않으면 전원에게 같은 답이 나온다. **이게 디폴트 실패 모드다.**
→ **막는 법:** 방법 A 가 `D` 를, 방법 B 가 `E` 를 개인화한다.
→ **게이트:** 사람 간 Top-10 Jaccard 를 **반드시 먼저 본다** (§6 첫 줄).

## 4. 방법 네 가지

### A. 결핍/과잉 프로파일 × KG 극성  ★ 본체

개인 *u* 의 섭취를 compound 축에 올려 **gap 벡터**를 만든다.

```
g_u[c] = (권장섭취 - 실제섭취) / 권장섭취        ← KDRIs 2020, 성·연령별
         나트륨·당·포화지방은 상한 기준으로 부호 반전
score_u(f) = Σ_c  F[f,c] · clip(g_u[c]) · E[c] · 신뢰도[c]
```

- `g_u` 가 사람마다 다르므로 추천이 **진짜로 갈린다**.
- `E` 가 극성(우울증 축)을, `g_u` 가 크기를 준다 → "부족하고 + 우울증에 이로운"
  compound 를 많이 든 음식이 뜬다.
- **설명이 바로 나온다:** "엽산 섭취가 권장의 54%, 엽산은 우울증 음성 연관
  (ProMENDA·NHANES 둘 다 +) → 시금치·렌틸". 근거 추적이 우리 KG 의 강점이다.
- 구현 비용 낮음. KDRIs 표(약 20 영양소 × 성·연령군) 입력이 거의 전부다.
- **PHQ-9 이 필요 없다.** 2번 분기(아래)에서 B 가 막혀도 A 는 살아 있다.

### B. 하위군별 `E`  — 논문 알고리즘에 가장 충실

`nhanes.py` 의 회귀를 KNHANES 로 돌리되 **전체 표본 하나가 아니라 층별로** 돈다.

```
층: 성별 × 연령대(19-39 / 40-64 / 65+) × [우울군 PHQ-9>=10 / 대조군]
    → E_g (compound 극성), q<0.05 만 채택
개인 u → 자기 층 g → P_u = (E_g × Fᵀ) × S
```

- 구조(`P = D×S`)를 그대로 두고 `E` 만 바꾸므로 **기존 코드 재사용률이 가장
  높다** (`e_mode` 에 모드 하나 추가).
- **위험:** 층별 n 이 작아지면 계수가 불안정하다. NHANES 전체 4,774 명에서도
  47 종 중 24 종만 q<0.05 였으니, 6~8 층으로 쪼개면 유의 compound 가 급감한다.
  → **shrinkage 필수** (층 계수를 전체 계수 쪽으로 축소). `shrunk` 모드와 같은
  패턴이다.
- **다주기를 합치지 말고 홀드아웃으로 쓴다.** §20 에서 다주기를 합쳤을 때 `E` 가
  나빠진 전례가 있다. 2014·2016 으로 추정 → 2018·2020 으로 검증.
- **외부 대조군이 있다:** JNH 2023 (수산물 섭취 ↔ PHQ-9, KNHANES 2014~2020,
  §9) 이 이미 같은 데이터로 식품군-우울 연관을 봤다. 우리 `E` 부호가 선행연구와
  맞는지 댈 수 있다. §15d 에서 NHANES `E` 와 ProMENDA 부호일치가 0.517(우연)
  이었던 것처럼, 이번엔 **기댈 기준이 있다.**

### C. 건강상태 하드 제약  ★ 본체
> 개인화의 실질은 점수보다 **제약**에서 나온다.

KNHANES 검진·설문에서 개인의 금기·주의 compound 를 뽑아 **필터 + 재순위**.

| 상태 | 제약 |
|---|---|
| 고혈압 | `C01330`(나트륨) 상한, 칼륨 가점 |
| 당뇨 / 내당능장애 | 당·정제탄수 상한 |
| 만성신장질환 | 칼륨 · 인(`C06262`) 상한 |
| 이상지질 | 포화지방산(`C00249`, `C01530`) 상한 |

- **규칙끼리 충돌한다** — 고혈압은 칼륨 가점, CKD 는 칼륨 상한. **우선순위를
  명시해야 한다** (안전 쪽, 즉 상한이 이긴다).
- **제약의 근거는 KG 추론이 아니라 KDRIs · 진료지침으로 둔다.** §18 에 "합병증
  추론에 증거가 없다" 가 기록돼 있다. KG 합병증 축은 **설명 경로로만** 쓴다.

### D. 섭취 이력 협업필터  — 비교군 · 수용성 보정

KNHANES 24시간 회상을 `(사람 × 식품) 섭취량` 행렬로 보면 그대로
implicit-feedback CF 데이터다.

```
S_cf  섭취 공동출현 기반 item-item 유사도
S_kg  우리 KG 의 성분 기반 유사도
최종 = α·S_cf + (1-α)·S_kg      → α 는 sweep
```

- **왜 필요한가:** A·B·C 는 영양학적으로 옳지만 "**안 먹을 음식**" 을 추천할 수
  있다. CF 가 "비슷한 한국인이 실제로 먹는 것" 을 줘서 누른다. 미국 FDC 음식만
  추천하는 문제도 이 축이 완화한다.
- 수업 과제의 "추천시스템" 틀에 가장 잘 맞는다 — CF vs 콘텐츠, cold-start,
  sparsity 논점이 자연히 생긴다.
- **음식 축 매핑을 피할 수 없다.** 단 **상위 300 다빈도 식품만** 매핑하면 섭취량
  커버리지 대부분을 잡는다. 전수 매핑은 불필요.
- 백분위 순위 평균 결합은 §25 에 이미 구현돼 있다.

## 5. 조합과 실행 순서

**A + C 를 본체, B 를 개인화 깊이, D 를 비교군.**

```
1단계  C : 금기 제약으로 후보 음식 필터            (안전)
2단계  A : gap × E 로 점수                         (개별성 · 설명)
3단계  B : E 를 개인의 층 E_g 로 교체              (논문 충실)
4단계  D : CF 순위와 백분위 앙상블로 결합          (수용성)
```

A·C 만으로 "개별 추천" 이 성립하고 설명 경로가 KG 로 끝까지 추적된다. B 는
비용이 싸지만 층별 n 때문에 효과가 안 날 수 있다. D 는 매핑 비용이 있다.

## 6. 평가 — 자를 먼저 정한다

**개별 추천에는 정답이 없다.** 레포의 기존 기준(논문 Top30 겹침)은 **쓸 수
없다** — 사람마다 다른 답을 내는 게 목표다. 그래서 자를 **코드 짜기 전에**
정해 둔다. 안 그러면 나온 결과를 보고 자를 고르게 된다 (`METHODS.md` §0 의
fitting 과 같은 함정).

| 지표 | 방법 | 막으려는 실패 |
|---|---|---|
| **개별성** | 사람 간 Top-10 Jaccard 중앙값 | 전원에게 같은 답 — **디폴트 실패** |
| **gap 축소** | 추천 3품을 섭취에 더했을 때 KDRIs 미달 영양소 수 감소 | 영양학적 무의미 |
| **제약 위반** | 추천 중 금기 compound 초과 건수 = 0 | 위험 추천 |
| **결과 정합** | 추천 점수 높은 식단을 실제로 먹는 사람의 PHQ-9 가 낮은가 (KNHANES 내 횡단) | `E` 방향 오류 |
| **홀드아웃** | 앞 주기로 `E_g` → 뒤 주기로 검증 | 과적합 (§20 전례) |
| **상식 검정** | Top-10 에 향신료 · 강화분말 · 시럽통조림이 있는가 | 100 g 기준 폭주 (§12 · §15d **재발**) |

마지막 줄은 농담이 아니다. **두 번 실패한 지점이라 게이트로 둔다.**

## 8. 결정하지 않은 것

적어 두지 않으면 나중에 "정한 것" 으로 착각한다.

- `E` 를 A 에서 어느 소스로 쓸지 — ProMENDA / NHANES / KNHANES 신규 / 앙상블.
  §27 에서 질적 판단이 두 번 틀렸으므로 **측정해서 정한다.**
- `clip(g_u)` 의 범위. 결핍을 어디서 자를지 (과도하면 한 영양소가 점수를 지배).
- `신뢰도[c]` 의 정의 — q 값 기반인지 소스 수 기반인지.
- C 의 제약을 하드 필터로 둘지 페널티로 둘지. 하드면 후보가 과하게 줄 수 있다.
- 추천 단위 — 단품인지 식단(끼니 조합)인지. 과제 요구를 다시 읽어야 한다.
